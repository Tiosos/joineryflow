## 0. Why this order

The worker is useless without documents, documents are useless without an
outbox feeding them, and the UI needs a working route. But the riskiest piece
is **none of those**: it is whether the triggers catch every write and the
dependent fan-out stays cheap. So B (outbox) lands and gets its tests before
any Meilisearch code exists, and the worker is built against an in-memory fake
before the real container matters.

## 1. Binding decisions

| Area | Rule | Source |
| --- | --- | --- |
| Engine | Meilisearch, pinned `v1.x` minor | Q574 |
| Sync | Outbox + worker + `make reindex` (swap-index rebuild) | Q575 |
| Outbox payload | Identity only — `(entity_type, entity_id)`; worker reads current state | spec §4.1 |
| Outbox delete | By locked `outbox_id`s, **never** by entity key | spec §4.2 |
| `codes` field | **No typo tolerance** — a near-miss number is a different record | Q541, spec §3.2 |
| Isolation | Server-built filter always carries `workspace_id` | Q576 |
| Authorisation | Types ⊆ modules the role can `read`; unknown types dropped silently | Q576 |
| Outage | `503 SEARCH_UNAVAILABLE`; no Postgres fallback | spec §5 |
| Never indexed | Secrets, money columns, bank / tax / ABN | spec §3.3 |
| Outbox writer | DB triggers | Q578 |
| Worker placement | Own compose service | Q577 |
| Types | Spec §3 table incl. `project`; area/room folded into items; people deferred | Q579 |
| Deleted / archived | Soft-deleted items never indexed; archived indexed with `archived=true`, hidden by default | Q580 |

### B. Outbox (Q578)

- [x] **B1** Migration `0033_search_outbox`: the table, one trigger function,
  a trigger on each source table (spec §3), and the dependent fan-out
  (project → children, area/room → items, cutlist → items, estimate_revision
  → estimate, vendor → orders), each guarded by `IS DISTINCT FROM` on the
  embedded columns. Backfill every existing row into the outbox. The
  docstring states that **this is the repo's first trigger** and why.
  Downgrade drops the triggers, the function and the table.
  *Done when:* `alembic upgrade head` then `downgrade -1` then `upgrade head`
  is clean on a seeded DB; the outbox row count after upgrade equals the sum
  of source rows.
  → **done.** Two plpgsql functions: `search_enqueue(kind, id_col)` on 15
  tables plus `estimate_revision` (enqueues its estimate), and
  `search_fanout(...)` on six parents behind `WHEN (… IS DISTINCT FROM …)`
  on the embedded columns — 22 triggers. The outbox's `entity_type` is
  CHECK-constrained to the 15 kinds. The six catalog tables keep their own
  kind because their PKs overlap (spec §3's `"{type}-{pk}"` id would have
  collided — corrected to `material-{table}-{pk}`). *Verified* on a seeded DB:
  outbox 76 rows = 76 source rows after upgrade; downgrade → upgrade clean;
  seeding **on top of** `0033` enqueues every kind (triggers catch seed data).
- [x] **B2** Trigger tests (`test_search_outbox.py`): INSERT / UPDATE /
  DELETE on each table enqueues exactly one row; a project-code rename
  enqueues its children; a plain item save does **not** fan out; a catalog
  write through `catalog/queries.py`'s dynamic SQL enqueues (the path grep
  misses). Add `search_outbox` to the suite's truncation lists.
  *Done when:* green in `make test`.
  → **done.** `tests/test_search_outbox.py`, 14 tests, including cascade
  (deleting a cutlist enqueues the item its `SET NULL` unlinks), the
  project-less order (Q554) and the entity-kind CHECK. `search_outbox` added
  to `conftest.TRUNCATE_TABLES`. *Verified:* full suite **664 passed, 9
  skipped** (8 of the skips are `meili`-marked).

### C. Documents, worker, reindex

- [x] **C1** `app/search/documents.py` — one builder per type (spec §3.1),
  batch-loading by id list, returning `None` for missing / excluded rows.
  First deliverable: the **per-type field table**, reviewed against spec §3.3
  before any builder is written.
  *Done when:* `test_search_documents.py` pins each type's field allow-list,
  its `codes`, its `url`, and the orphan-order workspace path (Q554).
  → **done.** One loader per outbox kind (15), each one named-column
  `text()` query. `archived` follows each record's own page: Q580's list plus
  what the iSample / Estimating Archive subtabs already show (rejected
  samples; rejected / expired / withdrawn estimates). Cancelled orders,
  inactive suppliers and closed projects stay visible — **an interpretation,
  raised with the user**. Found while checking against the seed: every
  seeded item's cutlist carries its own number, so `codes` is de-duplicated;
  four catalog tables hold rows with no `sku`, so the catalog link falls back
  to the description (the page's `q=` matches either). *Verified:*
  `tests/test_search_documents.py`, 12 tests; the §3.3 allow-list is pinned
  by planting sentinel bank / tax / terms / ABN values and the row's real
  money values, and asserting none reaches a document.
- [x] **C2** `app/search/worker.py` — the loop in spec §4.2 (lock → dedupe →
  build → send → delete-by-id → commit), with exponential backoff and a
  settings apply at start-up.
  *Done when:* tests against `FakeIndex` show (a) a batch processed, (b) rows
  retained when the send raises, (c) a row committed mid-batch survives.
  → **done.** Waits for Meili task **success**, not just enqueue — stricter
  than spec §4.2, because an accepted task can still fail and the outbox row
  is the only record that a document is owed. `get_index()` in `index.py` is
  the single factory. *Verified:* `tests/test_search_worker.py` (6), incl. a
  racing commit from a second connection. **End to end** against real Meili
  on the seeded DB: 149 outbox rows drained; `297830` finds the shared cutlist
  and its three items. Two findings: (1) `EST-2026-0001` also returned its
  siblings — fixed with `matchingStrategy: "all"` (spec §3.2), pinned by a
  `meili` test; (2) **four seeded catalog rows have `workspace_id` NULL**
  (custom_made, benchtop, appliances, equipment_hire — one each), so they are
  invisible on `/catalog` too; pre-existing seed gap, *not* fixed here. The
  loaders now skip workspace-less rows.
- [x] **C3** `app/search/reindex.py` + `make reindex` — build a
  `jf_search_{ts}`, apply the settings, swap, drop the old index.
  *Done when:* the `meili`-marked test shows search answering during the
  rebuild and the old index gone afterwards.
  → **done.** `documents.SOURCE_TABLES` gives the kind → table map, and a test
  checks it against the triggers **actually installed** (`pg_trigger.tgargs`),
  so the reindex and the outbox cannot silently disagree. *Verified:*
  `tests/test_search_reindex.py` (3) — a stale document disappears, a current
  one appears, no temporary index is left; the `meili` variant runs the real
  swap. **Not verified:** search answering *during* a rebuild — the tests
  check before and after the swap only.
- [x] **C4** Compose `search-worker` service (Q577).
  *Done when:* `make up && make migrate && make seed` leaves the outbox
  empty within seconds and `jf_search` holding the seeded records.
  → **done.** `search-worker` runs the api image with
  `python -m app.search.worker`, no `--reload`. *Verified:* `docker compose
  config` lists five services, and the worker's `process_batch` drained the
  seeded outbox (149 rows) into a real Meili in C2. **Not verified:** the
  `make up && make migrate && make seed` sequence itself — no Docker daemon
  here; CI's compose run (F1) is the first.

## 3. Risks

| Risk | Mitigation |
| --- | --- |
| A write path bypasses the index | Triggers (Q578); B2 exercises the dynamic-SQL catalog path explicitly |
| Fan-out storm on a project rename | Guarded by `IS DISTINCT FROM`; a project holds hundreds of rows, not millions |
| Cross-workspace leak | One filter builder, one isolation test per type in D1 |
| A near-miss number returns the wrong record | `typoTolerance.disableOnAttributes: ["codes"]`, pinned by the `meili` test |
| Index silently stale | `/search/health` outbox depth + age on `/it` |
| Tests need a container | Everything but the `meili`-marked tests runs on `FakeIndex` |
