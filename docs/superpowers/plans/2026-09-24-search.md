## 0. Why this order

The worker is useless without documents, documents are useless without an
outbox feeding them, and the UI needs a working route. But the riskiest piece
is **none of those**: it is whether the triggers catch every write and the
dependent fan-out stays cheap. So B (outbox) lands and gets its tests before
any Meilisearch code exists, and the worker is built against an in-memory fake
before the real container matters.

## 1. Binding decisions

| Area | Rule | Source |
| --- | --- | --- |
| Engine | Meilisearch, pinned `v1.x` minor | Q574 |
| Sync | Outbox + worker + `make reindex` (swap-index rebuild) | Q575 |
| Outbox payload | Identity only — `(entity_type, entity_id)`; worker reads current state | spec §4.1 |
| Outbox delete | By locked `outbox_id`s, **never** by entity key | spec §4.2 |
| `codes` field | **No typo tolerance** — a near-miss number is a different record | Q541, spec §3.2 |
| Isolation | Server-built filter always carries `workspace_id` | Q576 |
| Authorisation | Types ⊆ modules the role can `read`; unknown types dropped silently | Q576 |
| Outage | `503 SEARCH_UNAVAILABLE`; no Postgres fallback | spec §5 |
| Never indexed | Secrets, money columns, bank / tax / ABN | spec §3.3 |
| Outbox writer | DB triggers | **Q578 (proposed)** |
| Worker placement | Own compose service | **Q577 (proposed)** |
| Types | Spec §3 table incl. `project`; area/room folded into items; people deferred | **Q579 (proposed)** |
| Deleted / archived | Soft-deleted items never indexed; archived indexed with `archived=true`, hidden by default | **Q580 (proposed)** |

## 2. Tasks

### A. Infrastructure

- [ ] **A1** Compose + config. Add a `meili` service (pinned image, named
  volume `meilidata`, `MEILI_MASTER_KEY`, no host port). Add `.env.example`
  keys and `meili_url` / `meili_api_key` / `search_index` to
  `app/config.py`. Promote `httpx` from dev to runtime deps, with an upper
  bound per the `pyproject.toml` convention.
  *Done when:* `make up` starts four services and `curl meili:7700/health`
  from the api container answers `available`.
- [ ] **A2** `SearchIndex` protocol + `MeiliIndex` (httpx: add/delete
  documents, search, settings, swap, health) + `FakeIndex` for tests.
  *Done when:* unit tests drive `FakeIndex` through the same contract tests
  the `meili`-marked test runs against the real container.

### B. Outbox — **gated on Q578**

- [ ] **B1** Migration `0033_search_outbox`: the table, one trigger function,
  a trigger on each source table (spec §3), and the dependent fan-out
  (project → children, area/room → items, cutlist → items, estimate_revision
  → estimate, vendor → orders), each guarded by `IS DISTINCT FROM` on the
  embedded columns. Backfill every existing row into the outbox. The
  docstring states that **this is the repo's first trigger** and why.
  Downgrade drops the triggers, the function and the table.
  *Done when:* `alembic upgrade head` then `downgrade -1` then `upgrade head`
  is clean on a seeded DB; the outbox row count after upgrade equals the sum
  of source rows.
- [ ] **B2** Trigger tests (`test_search_outbox.py`): INSERT / UPDATE /
  DELETE on each table enqueues exactly one row; a project-code rename
  enqueues its children; a plain item save does **not** fan out; a catalog
  write through `catalog/queries.py`'s dynamic SQL enqueues (the path grep
  misses). Add `search_outbox` to the suite's truncation lists.
  *Done when:* green in `make test`.

### C. Documents, worker, reindex

- [ ] **C1** `app/search/documents.py` — one builder per type (spec §3.1),
  batch-loading by id list, returning `None` for missing / excluded rows.
  First deliverable: the **per-type field table**, reviewed against spec §3.3
  before any builder is written.
  *Done when:* `test_search_documents.py` pins each type's field allow-list,
  its `codes`, its `url`, and the orphan-order workspace path (Q554).
- [ ] **C2** `app/search/worker.py` — the loop in spec §4.2 (lock → dedupe →
  build → send → delete-by-id → commit), with exponential backoff and a
  settings apply at start-up.
  *Done when:* tests against `FakeIndex` show (a) a batch processed, (b) rows
  retained when the send raises, (c) a row committed mid-batch survives.
- [ ] **C3** `app/search/reindex.py` + `make reindex` — build a
  `jf_search_{ts}`, apply the settings, swap, drop the old index.
  *Done when:* the `meili`-marked test shows search answering during the
  rebuild and the old index gone afterwards.
- [ ] **C4** Compose `search-worker` service (**gated on Q577** — if the
  answer is "in-process", this becomes a FastAPI lifespan task instead).
  *Done when:* `make up && make migrate && make seed` leaves the outbox
  empty within seconds and `jf_search` holding the seeded records.

### D. API

- [ ] **D1** `GET /search` per spec §5, mounted in `main.py`. The filter is
  built only from `me.workspace_id`, the enum-validated types and integer

  *Done when:* `test_search_routes.py` covers workspace isolation (two

## 3. Risks

| Risk | Mitigation |
| --- | --- |
| A write path bypasses the index | Triggers (Q578); B2 exercises the dynamic-SQL catalog path explicitly |
| Fan-out storm on a project rename | Guarded by `IS DISTINCT FROM`; a project holds hundreds of rows, not millions |
| Cross-workspace leak | One filter builder, one isolation test per type in D1 |
| A near-miss number returns the wrong record | `typoTolerance.disableOnAttributes: ["codes"]`, pinned by the `meili` test |
| Index silently stale | `/search/health` outbox depth + age on `/it` |
| Tests need a container | Everything but the `meili`-marked tests runs on `FakeIndex` |
