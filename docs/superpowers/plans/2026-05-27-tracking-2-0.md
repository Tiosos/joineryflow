## T01 — Migration 0024

**File:** `db/alembic/versions/0024_tracking_2_0.py`

- `CREATE TABLE workspace_counter(workspace_id, name, next_value)` — composite PK, FK to `workspace(id)` ON DELETE CASCADE.
- `ALTER TABLE items` ADD: `jid_code VARCHAR(32)`, `jid_color CHAR(7)`, `var_boq VARCHAR(8) NOT NULL DEFAULT 'BOQ'`, `contractor_id BIGINT`, `total_amount NUMERIC(12, 2)`, `site_measure_notes TEXT`.
- CHECK constraints: `items_var_boq_check IN ('BOQ', 'VAR')`, `items_jid_color_check ~ '^#[0-9A-Fa-f]{6}$'`.
- FK: `items.contractor_id -> app_user(id) ON DELETE SET NULL`.
- Indexes: `idx_items_var_boq`, `idx_items_contractor`.
- Downgrade: drop columns, drop table.

**Acceptance:** `make migrate` runs clean and `make migrate` on a populated DB doesn't break existing rows (var_boq default fills retroactively).

## T02 — Counter helper module

**File:** `apps/api/app/counters/__init__.py`, `apps/api/app/counters/queries.py`

- `def next_value(db, *, workspace_id, name) -> int` — `INSERT … ON CONFLICT DO UPDATE SET next_value = workspace_counter.next_value + 1 RETURNING next_value`. Single statement is atomic; no explicit FOR UPDATE needed.
- One unit test: 100 sequential calls in a single test → values 1..100, no gaps.

**Acceptance:** `pytest apps/api/tests/test_counter.py` green.

## T03 — Item schemas + grid query extension

**Files:** `apps/api/app/items/schemas.py`, `apps/api/app/items/queries.py`

- `TrackingItemRow` Pydantic model adds the new fields. Mark `jid_code`, `jid_color`, `contractor_id`, `contractor_name`, `total_amount`, `site_measure_notes` optional.
- `_ITEM_COLS` in `queries.py` extended with the new selects + LEFT JOIN on `app_user contractor` for `contractor_name`, LEFT JOIN on `item_attachment WHERE kind='site_measure'` for `site_measure_attachment_id`.
- `list_items_for_project()`: accept new optional kwarg `availability: Literal['blocked'] | None = None`; when `'blocked'` add `AND (blocked subquery) > 0` to the WHERE clause.
- Result dict adds the new fields.

**Acceptance:** existing `test_items_routes.py` tests still pass; new test asserts new fields are present in payload.

## T04 — Bulk status endpoint

**Files:** `apps/api/app/items/schemas.py`, `apps/api/app/items/queries.py`, `apps/api/app/items/routes.py`

- New `BulkItemStatusIn(item_ids: list[int], status: str, note: constr(min_length=1))`.
- New `BulkItemStatusOut(updated: int, not_found: list[int], cross_workspace: list[int])`.
- New `bulk_patch_item_status()` in queries.py — single transaction. Per item id, run the workspace-isolation check (`_WORKSPACE_FILTER`) and either update + log or append to the appropriate list. Audit event `item.status.bulk` per item with `bulk_size`.
- Route: `POST /items/bulk-status` gated by `require_permission("tracking", "write")`. No `require_drafter()`.

**Acceptance:** new `apps/api/tests/test_tracking_bulk_status.py` covers happy path, missing note (422), RBAC deny, cross-workspace split.

## T05 — Tighten single-item status + patch fields

**Files:** `apps/api/app/items/schemas.py`, `apps/api/app/items/queries.py`

- `PatchItemStatusIn.note: str = Field(min_length=1)` (was `str | None = None`).
- Extend `_PATCH_FIELD_MAP` with `jid_code`, `jid_color`, `var_boq`, `contractor_id`, `total_amount`, `site_measure_notes`.
- `contractor_id` validation: before adding to updates dict, verify `SELECT 1 FROM app_user WHERE id = :cid AND workspace_id = :wid`. On miss, raise 422.

**Acceptance:** existing tests stay green after updating callers; new test asserts 422 on bad hex.

## Risk notes

- `var_boq NOT NULL DEFAULT 'BOQ'` ALTER on a populated DB needs the default to apply retroactively — PG 12+ handles this in a single statement.
- Multi-select state vs grid refresh — clear selection after every bulk action.
- `site_measure_attachment_id` join must use `kind='site_measure'` literal.
- `workspace_counter` UPSERT-RETURNING relies on PG ≥ 9.5; project already requires PG 16.
